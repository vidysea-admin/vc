## Criteria
- **CRISIS-AUTH** — authenticated turn route: when `text` is a string whose `crisisGuard` level is crisis or concern, a strict-schema failure (unknown key), an invalid `clientTurnId` (path separator, space, over 128 characters, non-string) or both no longer returns a plain 400. It returns the same crisis answer as a well-formed crisis turn (200, `escalated`, Tele-MANAS 14416 in the message, one escalation, one flag), Latin and Devanagari phrases, also for a student already rate limited and for an over-long text. The malformed fields are never stored, logged, escalated or echoed.
- **BENIGN-AUTH** — authenticated route: a benign `text` with the same unknown key or invalid `clientTurnId` is still the plain 400 `invalid_request` (no helpline field added), with no model call, no stored turn, no escalation.
- **KEEP400** — non-string `text` and unparseable JSON (and non-object bodies) stay a plain 400, whatever else the body carries.
- **CRISIS-ANON** — anonymous route: a crisis `text` with any extra key (unknown key, tenant or student ids, clientTurnId) gets the fixed crisis answer (200, `escalated`, 14416) and exactly one crisis counter, also for a client already rate limited; the extra keys are never read, kept or echoed. A benign `text` with extra keys stays the 400 that carries the helpline, with no model call and no counter; non-string text and non-JSON stay 400.
- **SCAN** — no extra scan: the crisis scan count of a malformed crisis turn equals that of a well-formed one on both routes (the existing per-turn scan is reused), and a malformed benign turn is scanned exactly once.
- **REG** — no regression: the chat, chat-privacy, chat-profile, chat-rank, student-openapi, anonymous-route and anonymous-zero-persistence test files stay green; the whole `apps/api` suite (355 tests) and `pnpm -r typecheck` are green.
