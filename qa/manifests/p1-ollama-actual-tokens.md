# Manifest — p1-ollama-actual-tokens
**Contract:** D-103 (record actual Ollama token usage next to the pre-request reservation); D-100 (paid real-model eval runs, Ollama-hosted models); contract B24.9 / A24 (the USD 50 per run and USD 200 per month caps stay on the pre-request reservation); contract B13 (no live call, no paid call from tests). Source brief `qa/evidence/p1-briefs/p1-ollama-actual-tokens.md`.
**Criteria:**
- C1 `OllamaProvider.generate` (`packages/providers/src/index.ts`) reads `prompt_eval_count` and `eval_count` from each successful (2xx, JSON body) `/api/chat` response and hands them to a new optional `afterResponse` hook as an `OllamaActualUsage`: `actual: "reported"` with `inputTokens`, `outputTokens` and `usd` (actual tokens x the table/override price) when BOTH counts are non-negative safe integers; otherwise `actual: "unreported"` with no figures (missing, one missing, negative, fractional, string, null, array, above the safe-integer range). Zero counts are valid. The hook is not called for a non-2xx response or when `beforeRequest` refused. `prepareOllamaProvider`'s factory passes it through.
- C2 The eval budget ledger (`packages/engine/evals/budget.ts`) gets an append-only `actual` line after each `charge`, carrying `actualInTokens`, `actualOutTokens`, `actualUsd` and the `reservedUsd` it belongs to (`BudgetRun.recordActual`); unreported or invalid figures are recorded `actual: "unreported"` with the reservation figure, never zero. `readLedger` fails closed on a corrupt `actual` line. `BudgetRun.usageSummary()` and `executeReal`'s result carry per-run sums (reported and unreported calls, actual tokens, actual USD, reservation total of the unreported calls).
- C3 The cap is unchanged: the reservation is still charged BEFORE the request (`beforeRequest` -> `run.charge`), `actual` lines never enter `spentUsd`, month spend or any cap check, a tiny reported actual does not free headroom, and the request that would pass a cap is still never sent.
- C4 Every Ollama REAL run (`runRealPath` in `packages/engine/evals/run-eval.ts`, which run-kb, run-probes, run-latency and run-h2h share) adds a `usage` object to its JSON report (also the abort report) and a usage block to its markdown: per-runner sums of reported calls / unreported calls / actual input tokens / actual output tokens / actual USD, `usdBasis: "notional"`, and the reservation total kept for unreported calls. The Spend figure stays the reservation total. With no `VC_REAL_MODEL` (default path) there is no `usage` section and no `actual` line.

## What changed
Branch `p1/ollama-tokens`, base `a555a90` (origin/main). Code and tests commit `e2f6194`; the manifest is a later commit. Edited in place, no new module besides this manifest.
- `packages/providers/src/index.ts`: new exported `OllamaActualUsage`; `OllamaProviderOptions.afterResponse`; `OllamaProvider.generate` validates the two counts after the body is read (before the content is parsed, since the tokens were spent either way) and calls `afterResponse`; `prepareOllamaProvider`'s factory takes an optional second argument. - `packages/engine/evals/run-eval.ts` `runRealPath`: wires `afterResponse` to `run.recordActual` next to the existing reservation hook; adds `usage` + `usageMarkdown` to the completed and abort reports. Gemini and other providers, run-live (its own per-minute charge) and the report renderers in `report.ts` are untouched.
- Tests: `packages/providers/tests/ollama.test.ts` (+6), `packages/engine/evals/budget.test.ts` (+5), `evals/p1-runners.test.ts` (+3 per runner x 5 runners, +1 default-path), `evals/real-bodies.test.ts` (+2: run-kb, run-probes, run-latency end to end through their real bodies).
- Design choice to confirm: the ledger is append-only and crash-safe, so the actual figures go on a NEW `actual` line right after the `charge` line (same `runId`, `reservedUsd` links them) rather than rewriting the charge line. Anything that reads only `charge` lines is unaffected.
