`caseUsable` is computed once per turn (`span.haystack`), so any turn with a mixed-case signal anywhere (a sentence-initial capital is enough) is judged "cased" for every mention in it. `nameLike` then only recognises an UPPERCASE neighbour as possibly-part-of-a-longer-name. A lowercase distractor name therefore clears both gates: the turn is "cased" (fallback doesn't fire) and the neighbour is "not name-like" (fragment-glue drop doesn't fire) — it passes through as a fully-trusted, unflagged fact.

## 2. Root cause: LOOP DESIGN, not execution

**Verdict: (a) LOOP DESIGN — specifically, the acceptance bar is unachievable by the chosen approach, not that the approach was built badly.**

Evidence against execution failure: every cycle shows strong engineering discipline — RED-first TDD pasted each cycle, a falsification table that mutates the fix and proves the right tests go red (F1-F13 in cycle 3 alone), an independently-coded eval classifier that must agree with the guard on a 90-row typed corpus, full verify-command reproduction (`pnpm -r test`, `typecheck`, `verify_contracts.py`) confirmed fresh by the checker every cycle, and a checker that re-runs every prior cycle's hostile probes directly against the real graph (never trusting the manifest's word) and confirms they all still hold. The checker's own cycle-3 verdict says this explicitly: "Every reproducibility claim ... holds exactly ... This FAIL is not about reproducibility, TDD, or falsification method." Nothing here is a bug in a sound approach that a sharper engineer would have caught; each fix precisely and narrowly closes the class it was shown.

Evidence for loop design: the same shape repeats 4 times running (cycle 0→1: substring anchoring fixed, but fragment-of-a-larger-expression opens; cycle 1→2: amount-expression parsing fixed, but type confusion (percent-vs-money) and substring-of-a-longer-name open; cycle 2→3: whole-entity glue-check fixed for the capitalised case, but the identical mechanism has a lowercase-shaped hole). Each fix is a **new, more specific heuristic** bolted onto a token/regex/capitalisation model of "is this string a whole, correctly-scoped fact." The task given to the guard is effectively **named-entity boundary detection and semantic-relatedness judgment over open, adversarial, multi-script, code-mixed natural language** — using no semantic model, only token shape and letter case. That is not a bounded bug surface; it's an approximation to an open problem, and the checker is explicitly adversarial with an unenumerated input space (any language construct a counsellor's transcript could contain).

**Is "a lexical/deterministic guard decides whether a string value is supported by a quote, at full confidence, with no human review" achievable at all?** No, not as a *complete* guarantee. The demonstrated pattern — capitalisation as the only "this might be a proper name" signal, "turn has any uppercase letter" as the only "case information exists" signal — is a genuinely reasonable, well-engineered *approximation*, and it correctly closes every case anyone has enumerated so far. But "is this glued word part of a longer proper name" is undecidable from token shape alone: English capitalizes many things that are not names (sentence starts) and fails to capitalize many things that are (ASR transcripts, casual typing, ISO-normalized text, most non-Latin scripts entirely — Devanagari, as the sibling T-005b diagnosis independently found for its own case-based boundary rule). Every fix cycle so far has been "add one more shape of glue/type/range detection"; the checker has found a new shape 4 times in a row with zero sign of the search space narrowing (cycle 3's finding is not an edge case — the checker explicitly notes mixed-case-turn-with-lowercase-distractor is "the common case for real transcripts").

**Can the acceptance bar ever converge under an adversarial checker with an open input space?** Not against "any wrong value kept unflagged = FAIL" as currently read. That bar is effectively "prove a negative over an unbounded space" — the checker's job (correctly, per B14: "any allow-list or deny-list guard has a hostile-variant test") is to keep finding a not-yet-enumerated hostile shape, and natural language has more of those than 3 fix cycles can exhaust. This is the same structural failure T-005b hit on crisis-guard sentence-boundary detection (`qa/debug/t-005b-guard-hardening-cycle3.md` §2): a deterministic guard is being asked to do open-ended natural-language judgment with a zero-tolerance bar, and the oscillation (fix A closes exploit A, opens exploit B in the same mechanism) is the observable signature of that mismatch, not of either the maker's or the checker's competence.

One difference from T-005b worth naming: T-005b's contract (B9) explicitly says false positives are the *safe* failure mode for that guard, so Option A there (strip the suppression logic) is contract-compliant today. T-013's B2 has no equivalent stated tolerance — its literal text ("Every fact shown or stored carries a source... Uncited facts are dropped or labelled unverified") doesn't by itself mandate the "zero exploits, full confidence" bar; that bar comes from B14's hostile-variant-test requirement as the checker has been applying it ("a wrong value kept unflagged = FAIL," restated verbatim in every cycle-1/2/3 verdict). B3 already puts a human in the loop for every write regardless of guard outcome, which is the structural opening for a narrower guarantee (see Option a below).

## 3. Recovery options

### (a) Narrow the guarantee: deterministic full-confidence support only for typed numbers + an enumerated value vocabulary with exact whole-mention match; every other string fact defaults to `needsReview`
Numbers already have a closed, typed vocabulary (`NUMERIC_KEY_KINDS`) and the amount-expression/range/boundary work from cycles 1-3 is real, converged engineering (the checker found zero new exploits in that surface in cycle 3 — only in the free-text entity path). Freeze that as the deterministic-and-trusted surface. For string/entity values, either (i) restrict full-confidence auto-keep to an enumerated, closed vocabulary (country names, `VALUE_ALIASES` groups — a fixed list, not open text) matched as an exact whole mention with the existing glue/particle rules as a secondary filter, or (ii) go further and make **every** free-text string value `needsReview` by default, since B3 already routes every fact through counsellor approval regardless. The open-ended "does this substring inside this open-vocabulary quote really refer to what the key claims" judgment — the thing that has produced 3 straight new exploit classes — stops being asked of the deterministic layer at all.
- Trade-off: recall/UX cost — more flagged facts, more counsellor clicks — but zero new fabrication risk from the entity-glue mechanism, and it stops the fix-cycle oscillation because the remaining deterministic surface (numbers) is the part that has actually converged.
- Smallest change with the least new code: it is closer to a scope cut (narrow what's claimed) than a rewrite.

### (b) Add an LLM verifier pass (Flash-Lite or similar) as a second opinion, replace the zero bar with a measured error rate
Keep the current deterministic guard as a first pass (cheap, fast, catches the obvious cases), and add a second, semantic pass — a small/cheap model asked "does this quote, in context, support this specific value for this specific key" — whose disagreement with the deterministic keep routes to `needsReview` instead of auto-approving. This directly targets the actual gap (semantic relatedness, not token shape) rather than adding a 4th heuristic to the same regex mechanism.
- Trade-off: real new engineering (latency, cost, a new failure mode — the verifier itself can be wrong or inconsistent, needs its own eval), and it's an architecture change to B6/B2, not a same-shape patch — likely its own unit, not a cycle-4 fix.
- Consistent with the AIOS pattern already used elsewhere (defense-in-depth: deterministic guard + cheap model judge), and named as the T-005b sibling's Option B follow-on shape too.

### (c) Change the acceptance bar from "zero exploits" to a measured fabrication rate on a frozen adversarial set, plus flagging
Freeze the checker's cumulative hostile corpus (every ISS-t-013-* exploit found across cycles 0-3, ~40+ cases) as a permanent regression/eval set, require 100% pass on it (already true), and change the *forward-looking* bar from "the checker may always find a new exploit class = FAIL" to "measured fabrication rate on this frozen set stays at 0, and any newly-discovered class is filed as an issue and either fixed in the next unit or explicitly risk-accepted with `needsReview` as the fallback," rather than stalling the whole unit every time.
- Trade-off: this is a contract/process change to how B14's hostile-variant-test requirement is *applied* to a guard doing open-ended NL judgment (not to guards over closed vocabularies, where zero-exploit is achievable and correct) — it needs to be scoped carefully so it doesn't quietly weaken B2 for the numeric/typed surface that HAS converged.
- Doesn't by itself fix the "new britain" hole — it would need to be paired with (a) or (b) to actually close the currently-known gap; on its own it only stops the oscillation, it doesn't improve safety.

### (d) Merge cycle 3 as-is behind B3 human approval, track residuals
Accept the current state (whole-entity check catches capitalised distractors, misses lowercase ones) as a documented residual — B3 means no fact reaches the student graph without a counsellor's approval regardless of `needsReview`, so the actual blast radius of an unflagged wrong value is "the counsellor doesn't get a highlighted warning, but still sees and can reject the card." Ship, log ISS-t-013-c3-1 as an open, tracked, non-blocking residual.
- Trade-off: weakest option — it's exactly what cycle-3's checker verdict already explicitly rejected ("a documented fabrication hole is still a fabrication hole against B2's bar... it is a value kept with zero signal to the counsellor that anything is uncertain"), and the counsellor's B3 backstop is a much weaker mitigant for an *unflagged, high-confidence* fact than for a `needsReview`-flagged one — the whole point of `needsReview` is to direct the counsellor's attention, and this hole defeats exactly that signal.

### Recommendation: (a)

(a) is the smallest recovery that fits the north star ("AI assists, the human decides") and the pattern this diagnosis (and the T-005b sibling) both point to: stop asking a deterministic/lexical mechanism to make an open-ended natural-language judgment it structurally cannot make reliably, and lean on the human-approval step (B3) that already exists for exactly this purpose. It keeps the genuinely converged, well-tested numeric/typed-amount surface (cycles 1-3's real engineering win) as the trusted deterministic core, and it stops manufacturing new open-ended entity-matching heuristics that the checker has now defeated 2 cycles running (c2-2 capitalised, c3-1 lowercase) in the same mechanism. (b) is the more thorough long-term answer and should be the next unit's target once (a) is scoped and shipped, not a cycle-4 patch to the current mechanism.
