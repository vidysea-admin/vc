# t057-kb-route-contract

The KB team published the draft /route contract (branch wave/kb-route c5c2b911, not merged/deployed; VC_KB_ROUTE stays OFF). Align VC route() built earlier (source 2: it assumed POST /route {q,k}) to the real contract: Request GET /route?q=<text>&k=<n>, k default 5 max 20, same auth and search scope as /search. Response 200 {query, hits:[{turnId, sessionId, score, turn, session}]} = same hit shape as /search (score BM25 normalised (0,1], only orders within one response, not comparable to /search scores; transcript hits only). Response 503 {error:"route_timeout"} on its hard 3 s deadline; first cold call may return route_timeout once. Changes: switch to GET with encoded query params; treat 503 route_timeout as a route-only miss (fall back to /search immediately, do NOT increment the shared base-URL breaker, and do not mark route unsupported for the full cooldown: a short skip e.g. 10 s is enough); keep 404/405/501 as unsupported; set the route timeout cap to about 3.5 s. Tests first. Run the mcp/university-kb test suite + tsc. Write qa/evidence/t057/kb-route-contract.md.
