### R1 — trusted age and guardian-consent mapping is missing (Q2, Q5)

The host token generator supplies only id and role (.worktrees/quest-pathlynks-backend/utils/tokenUtils.js:6-10); verifyToken assigns the verified user at :22-24. The plan names no authoritative age/consent source. G6 is minimal-data provider-egress authorization, not a verified per-student guardian-consent assertion.

Fix: name the trusted server-side source and exact mapping for age and guardian consent, used identically by text and voice; strip/ignore caller-supplied student, age, consent and tenant headers/body facts. Missing/unverified values must retain the central fail-closed behavior; never synthesize consent=true to make the pilot work. Define the authenticated user-role policy for student chat/mint and preserve existing authorized history readers explicitly. State how the authorized live account is tested if a trusted consent signal is unavailable. Add positive consent/adult fixtures and unknown-age/false-consent/spoofed-header fixtures proving provider/tool/persistence behavior. This can be resolved within the approved implementation scope; an absent real consent source remains an honest live-proof blocker.

### R2 — host history append can bypass central privacy and retry semantics (Q2, Q3)

Evidence: the host currently saves the raw message and live reply into pathlynks_ai_sessions via replaceOne (.worktrees/quest-pathlynks-backend/controllers/pathlynks_quest_controller.js:1089-1101). plan.md:40 says to append central-backed turns while preserving that history contract but gives no storage policy. Central chat deliberately separates the live response from redacted persisted turns (apps/api/src/chat.ts:766-773, :866-874), stores no text on several consent/safety/failure paths (:803-810, :846-853), and the history schema carries textStored (packages/schemas/src/student-api.ts:140-149). A 200/state=ok is not proof that text was eligible for storage. Existing host requests also have no stable clientTurnId (frontend src/services/pathlynksQuestService.js:51), while central replay uses it (packages/schemas/src/student-api.ts:103-109).

Fix: define one explicit source of truth for new persisted turns, with the legacy read envelope retained and old records preserved. Do not mirror the raw request or unredacted live reply into host history. Specify how consent/textStored, provider-failure and quiet-crisis paths prevent a new host copy; source new history from eligible redacted persisted central turns, or document an equivalently enforced policy. Define tenant+student+allow-listed island+role -> thread ownership and the create/reload/parallel-request/retry rules. Name how a stable turn id crosses the host bridge and how history append/retrieval deduplicates it without a second model call. Verify PII canaries and unconsented text are absent from every new host/central write, plus reload, concurrent sends and timeout-after-success retry. Preserve current parent exclusion and explicitly account for the existing counsellor/superadmin history access in utils/questAccess.js:43-68, :113-127; do not silently broaden access or confuse a history reader with the student's own identity.

### R3 — personalized voice is not connected to the existing Quest Guide surface (Q3, Q5)

Name the same-origin host mint route, its auth/access policy, request fields and returned session/thread envelope. Specify which existing functions own the bridge and the widget/host response mapping, keeping the central anonymous mint schema/flow compatible. Require an end-to-end host browser walk (permitted, denied and unavailable mic; same-thread history; reload; cross-student mint refusal) in addition to standalone widget tests. Keep tokens transient, out of URL/DOM/storage, and preserve single-use/origin/expiry checks.
