## 1. Scope (in)
1. **Text chat endpoint** (threads for Pathlynks-authenticated students) and **live voice endpoint** (Gemini Live over WebSocket, D-085). **Voice transcripts persist into the same thread history as text**, so the student sees one WhatsApp-like history (D-086); audio itself is not stored [ASSUMPTION]. **Voice stays disabled for real students until A10 passes.**
2. **Anonymous mode (text only; no public voice route exists):** public text route answers generic KB questions only; **VC persists nothing** (no Db, checkpoint, outbox, trace text, log text, gap counter). Personal questions return `sign_in_required`. The claim is about VC storage only; provider and KnowledgeBase handling are stated separately (A15c; production basis approved in D-086 and recorded in the B13 amendment).
3. **The existing KnowledgeBase API is the RAG, used as-is (D-087).** VC calls `POST /ask`, `GET /search`, `GET /citations/:claimId`, `GET /gaps`, `GET /sources` of `D:/KnowledgeBase` through `mcp/university-kb`, with a scoped key. VC keeps no copy of KB content in `D:/vc`, writes no pages and runs no page-authoring programme. Nothing in KB is changed unless a capability in section 7 truly cannot be served. No KB answer = the fixed "no sourced answer yet" text.
4. **Structured answer:** `claims[]`, each `{text, kind: number|country|fact, sourceIds[], verified}` plus `sources[]` and `profileFactsUsed[]`. A `sourceId` is a KB claim id returned by that same turn's `/ask` or `/search` call. `verified:true` means the id resolves through `GET /citations/:claimId` to a claim whose evidence turn and session still exist. Numbers and country names are also checked against the claim text (the part B2 auto-proves). Any other claim without a resolvable source is dropped or returned `verified:false` and shown flagged, never presented as sourced (B2). The umbrella "every sentence" claim is NOT made.
5. **Profile ranking** for authenticated students from the profile facts available (scope item 10). **Weights are configurable; the default goal is student success, the best possible outcome personalised to the student** (D-086) [ASSUMPTION: a default weight vector over fit, cost, scholarship chance and visa ease, proposed at U0 for Umesh to review, reported in the response as `rankingProfile`]. Numbers come from KB data, not the LLM (a new requirement, modelled on H2).
6. **Coverage-gap report:** authenticated-mode gap counts stored in `virtual_counsellor`, plus a country-by-theme probe of KB `/search` and KB `/gaps` (knowledge-health gaps). VC computes coverage itself, so no KB endpoint is added.
7. **Guards:** a deterministic no-quote guard keyed on a VC-side `speakers.json` (names plus transliterated/Devanagari aliases; **default-deny**: a listed speaker is never named unless Q8's permission list says so); authenticated-student gate (Pathlynks-authenticated = consented, D-086); B1 no-drafting guard (existing `no-script`) kept.
8. **Coach first, tool-aware (D-087, Q2):** the VC coaches first (asks, structures, gives feedback on the student's own draft) and **knows every VC tool and feature and uses them to help the student**: KB answers and sources, ranking, profile view/correct/confirm, coverage and "not covered yet" answers, export/erasure, text/voice switch. A request for the VC to write an essay or SOP for the student is turned into coaching; drafting is **not** granted (B1 stays). A capability manifest skill is the single list the model is given, and a test keeps it in step with the registered tools.
9. **Crisis defaults for students with no connected counsellor (D-087, Q11):** from `qa/evidence/crisis-research-20261017/proposal.md`: a fixed safe message with Tele-MANAS 14416 (free, 24x7), asks who the student's safe adult is, **no promise of secrecy**, **keeps talking** and re-checks risk every message, never gives method information, **every flag is logged** (authenticated: who/when/level/action), and the **human-alert route is not enabled until the CEO "Nights" decision**; until then the Tele-MANAS hand-off is disclosed to the student plainly and no counsellor is promised. Unsure, indirect, Hinglish and voice cases count as the higher level. Zero liability is not achievable; this minimises exposure. Anonymous mode: fixed message, no record (Q7).
10. **Profile sources (D-087, Q15), both accepted:** (a) a profile supplied by Pathlynks for the authenticated student; (b) facts extracted from the chat that **the student confirms**. Each fact carries `source: pathlynks | student-confirmed`; an unconfirmed chat-extracted fact is never used for ranking or personalisation.
11. **API surface:** OpenAPI 3, `/v1`, JWT + tenant (B21), error model, idempotent turns, profile and fact-confirmation routes.
12. **Languages:** tested for English and Hindi/Hinglish only; other languages are best effort and explicitly untested.

## 2. Non-goals
VC-owned UI/chat page/login/Hindi labels; avatar, video, booking; **ghost-writing essays or SOPs**; changing the crisis escalation recipients (human alert waits on the CEO Nights decision); application drafting; Career Library; student PII in the KB; KB content copies in `D:/vc`; a KB page store, page endpoints or page authoring; web or training-data answers; claiming pre-send enforcement for voice.

## 4. Head-to-head (release gate, D-083)
60 questions, >= 10 countries, 20 profile-personalised (synthetic profiles, B13), 20 Hindi/Hinglish [ASSUMPTION]. Experts answer independently and never see VC output; blind pairwise judging, randomised order, judges did not write the expert answer; accuracy, completeness, source quality, profile fit, safety (oct15_3:64-87). Threshold [ASSUMPTION]: equal-or-better on >= 85%, no safety-failing answer, A1 and A3 met. An LLM judge may pre-screen, never decides. Human effort [ASSUMPTION estimate]: ~20 expert-hours to write 60 answers plus ~10 hours per judge for 2 judges. **Ownership of expert answers, golden questions and the anonymisation sign-off is part of Q6.**
