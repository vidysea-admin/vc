## 4. Risks and gates
- **Voice cannot meet pre-send hard rules.** Gemini Live speaks before text guards run. B2 citations, B1 no-quote and crisis are monitored, not enforced, in voice: a spoken breach cannot be unsaid. Hence a B6 amendment, A9b (the audit demonstrably fires), A10 with the crisis set and the 2 s bound (D-088 Q5), and voice disabled until A10 passes (A20). D-086 keeps Gemini Live with persisted transcripts.
- **Production data basis: approved (D-086).** Real minors' text and voice go to Gemini in production; authenticated `/ask` calls may also reach the KB's LLM provider and Tavily (G6), and anonymous mode processes minors' text with no sign-in (search-only). The B13 amendment records provider terms, retention and DPDP basis and names each processor. Until it is signed, G-PROD blocks real-user exposure, the public anonymous route and partner publication.
- **KB web fallback and logging (G3, G6):** the KB `/ask` can send query text to a web search provider and writes job-ledger rows (read 2026-10-17: rows hold kind/status/provider/model/costUsd/error, no query text by construction; provider error strings unverified). `/search` is read-only and the KB has no access logger; KB-side handling stays outside VC's control. VC drops web answers (a recall loss: any `web_used:true` answer becomes a no-answer) and keeps anonymous turns on `/search`. The fully clean fix is an optional KB change (per-key switches), not required for P1.
- **Crisis liability is minimised, not removed (D-087).** The proposal states zero liability is not achievable. Open outside P1: the CEO Nights decision (human alert), whether minors are served before counsel clears DPDP, and who owns the clinical-safety policy; Tele-MANAS adolescent and language coverage is unverified (test-call before launch). P1 ships the disclosed Tele-MANAS hand-off and complete flag logs. Anonymous mode keeps only a text-free counter, so a crisis there is not recorded as an event with content.
- **KnowledgeBase API fit (D-087):** the KB is used as it is. "Worldwide" answers are only as wide as KB content, so most countries show as gaps, not authored pages. The source-kind mapping (G1) depends on what `/sources` and session metadata expose; undeterminable kinds are treated as WhatsApp, which lowers quality before it risks a leak. KB outage returns the fixed no-answer text.
- **Head-to-head bar is lower (D-088):** 60% equal-or-better is weaker than the earlier 85%; A1 and A3 are kept as required companions so a 60% pass cannot hide uncited or named-speaker answers. Judges and authors come from one counsellor team; the split is a maker condition [ASSUMPTION].
- **Profile quality:** chat-extracted facts can be wrong; used only after the student confirms (A16b). Pathlynks-supplied profiles are trusted as supplied.
- **Consent is outside VC (D-086):** Pathlynks-authenticated = consented; VC adds no consent-claim verification, so a wrong assumption at Pathlynks is not caught by VC. Existing consent/purpose records (`packages/db/src/consent.ts`) need a contract decision on whether they remain (U0).
- **Student identity is new (R8):** the current JWT code has no student claim; U8 and U10 cannot start before the B21 student-JWT amendment.
- **Coach-first (D-087):** the line between coaching and drafting is judged by A21(a) fixtures and the head-to-head; drafting stays out.
- **Mock vs real:** mock tests prove plumbing only; model behaviour is proved by REAL runs, each under the A24 budget cap.
- **Environment:** full C: OOMs the suite (ENVIRONMENTAL). Build in isolated worktrees, never in dirty `D:\vc`. No push, deploy, partner exposure or paid run without Umesh's gate.
