## 2. partners.ts (814 lines) - the partner registry
- Storage: Mongo collection `partners` (`PARTNER_COLLECTION="partners"` partners.ts:147; store hard-codes `db.collection<PartnerDoc>("partners")` :259) in the `virtual_counsellor` DB, unscoped Db. `_id = partnerId`. NOTE: grep finds NO `partners` declaration in packages/db/src or packages/db/tests (collection is accessed raw via db.collection) - F2 should confirm what the db-init test does about it.
- Doc shape `PartnerDoc` partners.ts:208-216: `{_id, partnerId, name, keys:{pub:{hash,prefix,rotatedAt}, srv:{...}}, allowedOrigins:string[], status:"active"|"revoked", createdAt}`. `PartnerSummary` (no hashes) :219.
- Partner id `/^[a-z0-9-]{2,32}$/` :44; partnerId IS the tenant id of everything its server key reaches (chat.ts ~:895 `tenantId: partner.partnerId`). Reserved: RESERVED_PARTNER_IDS :52 (sandbox, admin, system, root, default, internal, plus name+separator+suffix), KNOWN_TENANT_IDS :54, env VC_RESERVED_TENANT_IDS :59, VC_PARTNER_OWN_TENANTS :111.
- Key format: `vck_(pub|srv)_<partnerId>_<43-char base64url of 32 random bytes>` (:136-141); pub = page key (public chat/voice routes only, CORS-eligible, origin-locked), srv = server key (student routes only, never CORS). Stored: HMAC-SHA256(key, VC_PARTNER_KEY_PEPPER) hex (`hashPartnerKey` :310) + display prefix (`vck_<scope>_<id>_` + 4 secret chars, :143). Raw key returned once (add/rotate). Pepper >= 32 chars (:144, `partnerPepperFromEnv` :284).
- Verify: `createPartnerRegistry({store,pepper,reservedIds,ownTenants})` :600; `authenticate(key, scope)` :637 (timingSafeEqual vs stored/dummy hash; scope must match; status active; not reserved). Whole partner list cached, TTL 60 s (`PARTNER_CACHE_TTL_MS` :146) => revoke/rotate effective within 60 s on a running server. Fails closed (`PartnerRegistryUnavailableError` -> 503).
- Reusable exports (all take a `PartnerStore`, so an admin API can call them against the same Mongo store): `addPartner(store,{name,origins?,id?},ctx)` :383 -> `{partner,keys:{pub,srv}}`; `rotatePartner(store,id,scope,ctx)` :418 (compare-and-set on old hash + still active); `revokePartner(store,id)` :451; `listPartners(store)` :458; `createMongoPartnerStore(db)` :258; `normalizeOrigin` :337; `PartnerOpContext {pepper, reservedIds, ownTenants, now, randomBytes}` :365; `PartnerError(code)` codes :150-158; `partnerCliFailureLine` :176; `PartnerStore` interface :228 (get/list/insert/update; `PartnerPatch` :247). NOT supported today: editing allowedOrigins/name of an existing partner (PartnerPatch type allows it, no op function does), un-revoke, delete, per-partner rate/guardrail/tracking config.
- CLI: scripts/partner.ts (60 lines); package.json `"partner": "tsx scripts/partner.ts"` -> `pnpm -C apps/api partner add <name> [--id <id>] [--origin <https://site>]... | rotate <id> --scope pub|srv | revoke <id> | list [--check]` (`runPartnerCli` partners.ts:487, `PARTNER_USAGE` :466). Needs MONGODB_URL, VC_PARTNER_KEY_PEPPER (+ optional VC_RESERVED_TENANT_IDS, VC_PARTNER_OWN_TENANTS). Exit 0 ok / 1 refused / 2 usage.
- Origin lock: `normalizeOrigin` (https://host[:port], or http on localhost/127.0.0.1; no path/wildcard) partners.ts:337. Enforced (a) CORS: preflight allowed if origin is in ANY active partner (`originAllowedByAnyPartner` :652); real request only if its pub key's list has the origin (withPartnerRoutes :800-811); (b) anonymous text route anonymous.ts ~:467-475 and anonymous voice session voice.ts:1794-1798: an `Origin` header not in the partner's list = uniform 401 (no Origin header = allowed, "not a browser").
- Rate limit: no per-key rate field in PartnerDoc. Limits come from `resolveLimits(deps.limitsForTenant?.(tenantId))` (packages/schemas/src/student-api.ts:225; DEFAULT_LIMITS :209-219: requestsPerMinute 30, anonymousRequestsPerMinute 10, voiceMinutesPerMonth 60, voiceSessionMaxMinutes 20). Anonymous bucket = `partnerId \0 clientKey` (anonymous.ts ~:503, window 60 s `ANONYMOUS_WINDOW_MS` :75); student text bucket = `tenantId \0 studentId` (chat.ts:860-862). `limitsForTenant` is an optional startApi hook (chat.ts:252) not wired to any store today.
- Usage: `noteTurn(partnerId)` / `usage()` are in-memory only (partners.ts:667-672), called only by the anonymous route (anonymous.ts:537); lost on restart; student/voice partner turns are not counted there.
- Integration point: admin "register host sites / API keys" = call addPartner/rotatePartner/revokePartner/listPartners with `createMongoPartnerStore(db)` and the same pepper/reservedIds; add an update op for origins/name.

## 3. auth.ts (460 lines) and who issues JWTs
- Verifies (jose `jwtVerify`): signature with strict alg allow-list RS256/ES256 (HS256 only alone with its own secret; "none" refused) auth.ts:130-217; `exp` required; `iss` == VC_JWT_ISSUER; `aud` if set; clock skew default 30 s, max 300 (:97-98); token max 8192 chars (:100). `createJwtVerifier` :299 requires claims `exp, iss, tenant, counsellorId, role`; `contextFrom` :251 -> `AuthContext {tenantId, counsellorId, role}`.
- Roles: `API_ROLES = ["counsellor","admin","approver"]` auth.ts:37. Student verifier (separate env, configurable claim names, role must be "student") :316-427; `refuseTenantClaims` :436 (blocks a JWT tenant equal to a partner id); `bearerToken` :456.
- Env NAMES (counsellor): VC_JWT_ISSUER, VC_JWT_AUDIENCE, VC_JWT_ALGORITHMS, VC_JWT_PUBLIC_KEY, VC_JWT_JWKS_URL, VC_JWT_HS256_SECRET, VC_JWT_CLOCK_SKEW_SEC (auth.ts:104-112; .env.example:36-45). - Issuer: NONE in the repo. auth.ts:4-6: "Every request carries a JWT issued by the client backend (for Pathlynks, its backend); VC has no login and no password store." grep for login/password/argon/bcrypt in apps/api/src: no auth hits (only URL-userinfo redaction main.ts:145, partners.ts:173/348). `SignJWT` appears only in voice.ts:441 (`mintAnonymousVoiceToken`) and voice.ts:466 (`mintVoiceToken`): short-lived HS256 WebSocket tickets (secret env VC_VOICE_WS_SECRET >= 32 bytes, VC_VOICE_WS_BASE_URL; index.ts:339) - not counsellor/admin tokens. - Today `role: "admin"` = a Pathlynks-issued token carrying the admin claim (routes executeErasure/exportStudent, server.ts:664-675). The counsellor verifier is wrapped by `guardCounsellorVerifier` (index.ts:669, used :804).
- Integration point: an Admin Console login has nothing to extend - it needs a new issuer (credential store + token signing) or a third verifier env block with its own issuer/audience, modelled on STUDENT_JWT_ENV (auth.ts:320).

## Cross-cutting notes for the plan
- Partner id doubles as tenant; `VC_PARTNER_OWN_TENANTS` (partners.ts:111) lets a `pathlynks` partner exist alongside a real JWT tenant of the same name.
- Secrets discipline in this code: env NAMES only in errors; keys never logged; `describeStartupError` redacts (main.ts:156). An admin API must return raw keys once, never store them.
- No existing Mongo collection for admin users, knowledge sources, guardrail config, or turn-level usage with cost. Only per-student monthly usage (`recordStudentUsage`) and in-memory partner turn counts exist in apps/api.
