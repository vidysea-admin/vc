## Method
- Probe script (scratchpad, not in repo): `plprobe.mts`, run as `npx tsx plprobe.mts` from the repo root. Env from `.env`; key names used: PATHLYNKS_DB_PASSWORD, PATHLYNKS_DB_CA_FILE, PATHLYNKS_ALLOW_PRIVILEGED_ROLE, VC_TEST_PATHLYNKS_USER_ID.
- Connection: `buildPgConfig` + `defaultConnect` (`mcp/pathlynks/src/connect.ts:41,78`), source `pathlynks-db` of `config/sources.json` (sslmode `verify-full`, `rejectUnauthorized: true` plus the RDS CA bundle from PATHLYNKS_DB_CA_FILE). Reads use the real `createPathlynksPort` (`mcp/pathlynks/src/port.ts:113`) with the same table map as `pathlynksTablesFrom` (`apps/api/src/admin-routes.ts:1038`).

## 1. Connect
CONNECT ok in 552 ms (probe timeout widened to 10 s; the shipped port uses 3 s connectionTimeoutMillis and still fits). TLS verified (`current_setting('ssl') = on`, verify-full with CA). The earlier security-group timeout on 5432 is gone: no timeout, no auth error, no TLS error.

## 2. Read-only session
- `SET default_transaction_read_only = on` then `SHOW default_transaction_read_only` = `on`; `current_setting('transaction_read_only')` = `on`.
- Finding: `has_table_privilege(current_user, t, INSERT/UPDATE/DELETE)` is TRUE for at least one allow-listed table (role `pathlynksadm` is privileged; SELECT is true on all 13). This is the known G1 case (answered 2026-10-26): `PATHLYNKS_ALLOW_PRIVILEGED_ROLE` is set, so the port skips only the connect-time refusal (`port.ts:257`; the port status stays `unchecked`). SELECT-only SQL, the read-only transaction and the 3 s statement timeout still hold. The guarantee against writes is therefore the session setting plus code, not the role.
