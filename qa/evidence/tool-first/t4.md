## Design facts
- Tools: `vidysea_journey_maps`, `vidysea_applications`, `vidysea_visa`, `vidysea_favourites`, `vidysea_saved_scholarships`, `vidysea_progress` (all graph, authenticated only). Only the verified `auth.studentId` reaches the port; `namesAnotherStudent` still runs first; anonymous never reaches the tool node; crisis runs before routing.
- Output is deterministic text over allow-listed columns only. Ids, notes, links, raw JSON, checklists and comments are not in any allow-list and are also absent from the port SQL. Dates (pg `Date` or ISO text) print as YYYY-MM-DD; statuses show `application_created` as "application created". The Pending milestone count is shown, and the three buckets are not assumed to sum to the total (t2-live.md finding).
- D-133, no data: a zero-row read replies "You have no <x> on Vidysea yet. Here is how to start:" followed by the T1 recipe text (`navigateSteps` over the synced catalogue, recipe id + an ask its own pattern matches, guarded by `recipe.pattern.test`). No recipe text is duplicated. With no hub page in the catalogue it is the plain "nothing yet" line, never an invented link.
- D-133, has data: a count/line summary built from the rows. `vidysea_progress` reads shortlist + the five tables in parallel (one 5 s budget), shows a per-category count (a failed or unsupported read shows "can't see right now"), and picks the "Next step" from a fixed table (shortlist, journey map, application, visa), with the matching recipe steps. No LLM, no arithmetic by a model (T5 builds summaries).
- TF-10: empty list = "nothing yet" (+ guidance); `ok:false`, missing method, throw, hang, or rows that cannot be shown = the one line "I can't see your Vidysea data right now", no reason, host or SQL. If every progress read fails it is the same single line.
- Engine port methods are optional on `VidyseaReadonlyPort` (like `getPathlynksSnapshot`) so existing test doubles still compile; the production port requires them.
