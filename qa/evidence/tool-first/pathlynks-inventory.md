## 0. How the Pathlynks student UI is shaped (differs from Vidysea)

- Real routes, not a hub. Student pages are Next.js routes under `FE:src/app/(admin)/(student)/` (my-report, my-matches, my-roadmap, my-resources, career-compare, favorite, my-academics, my-assessments, messages, help-faq, settings, pending-validations, achieve-works, `career-quest/*`) plus `(admin)/career-repository`, `(admin)/resource-library`, `(admin)/dashboard/studentPanel`, `(admin)/profile/studentProfile`. So a path-only link works with VC's `SAFE_ROUTE` (no `?section=` problem, Vidysea gap G1 does not apply).
- The sidebar is DB-driven (`groupAccessItems(userData.access, role)`, `FE:src/layout/AppSidebar.jsx:150`), so which entries a given student sees depends on role/menu rows, school settings (`my-academics` hidden unless `allow_academic_upload`, `AppSidebar.jsx:154-156`; `subject-selection` always hidden, `:160-162`). The fixed student path list is `STUDENT_PATH_ICONS` (`AppSidebar.jsx:66`).
- Gates a link must respect: islands lock by `questProfile.islandStates[key].unlocked`; `my-roadmap` and `my-resources` need a combined report (`REPORT_LOCKED_PATHS`, `AppSidebar.jsx:91`; `FE:src/components/career-quest/navRegistry.js:21-22`). Possible `basePath` `/pathlynks` (`FE:next.config.js:3`, `FE:src/utils/basePath.js`); VC links must stay relative and let the host add it.
- Three stores: (a) Postgres (users, assessments, fit scores, saved careers, compare, reports, messages), the only one VC's `pathlynks-db` source covers; (b) **MongoDB `pathlynks_journey`** for everything in Career Quest (`SCH:services/pathlynksMongoDB.js:42-49`, collections below); (c) S3 for proof files/uploads. The DB is read via three services, one Postgres (assumption: one DB `pathlynks_prod_121125`, as `config/sources.json` implies).
- VC reads today (6 Pathlynks tools, `packages/engine/src/student/graph.ts:226`, port `mcp/pathlynks/src/port.ts:104-219`): profile (users + user_grade + grade), saved careers, compare list, assessment status, career fit (category/subcategory/trait scores), combined-report overview. Owner predicate: `u.id = $1 AND u.deleted_at IS NULL AND u.disabled_at IS NULL` (`port.ts:112`). "OWN" below = that predicate on `users u`.

## 2. Specific findings

### 2a. Career Quest state is in MongoDB, not Postgres

Selected career and picks, the whole university island (preferences, shortlist, target), goals, activities, year plan, skill activities, XP/levels, island lock state, persona graph and AI sessions live in `pathlynks_journey` collections `pathlynks_quest_profiles`, `pathlynks_goals`, `pathlynks_activities`, `pathlynks_skill_activities`, `pathlynks_persona_graphs`, `pathlynks_ai_sessions` (`SCH:services/pathlynksMongoDB.js:42-62`; handlers cited in rows 6-12). VC's `pathlynks-db` source is Postgres only (`config/sources.json`), so "what is my target university / which careers did I pick / what are my goals" is unreadable from Pathlynks. The only copy VC can read today is whatever the Vidysea snapshot carries (`graph.ts:272`: selectedcareer, recommendedcareers, careerpicks, targetuniversity, universitypreferences), and only for SSO-synced students.

### 2b. Saved careers read mixes three kinds of save

`student_saved_careers` holds `CATEGORY`, `SUBCATEGORY` and `CAREER` saves in one table, keyed `(student_id, id)` with `id` pointing into three different catalogues (`CAR:controllers/career_recommendation_controller.js:3789` takes `type` from the request body; per-type joins at the favourites reader `:3970`). VC's `savedCareers` SQL joins `career_option` on `sc.id` with no `save_type` filter (`mcp/pathlynks/src/port.ts:119-121`). Effect: a saved category or subcategory can be shown as an unrelated career (id collision) or dropped. The migration says `id` references `career_option` and no later migration drops that FK (`SCH:migrations/20251212100022-create-student-saved-careers.js:14-19`); whether the live table still carries it is [UNVERIFIED] without the DB.

### 2c. Fit scores have two spaces

The student sees `*_canonical` fit tables when an external/AchieveWorks overlay applies and the kill switch is on; otherwise legacy (`SCH:services/canonical/fitSpace.js:7-52`, rule steps `:14-37`). VC reads only legacy (`port.ts:154-171`), so for external-report students VC can disagree with the screen.

### 2d. Fit rows may not exist yet

The first calculation is triggered server-side after an assessment submit (`student_aassessment_controller.js:1836,1958`, `SCH:services/fitScoreTrigger.js`) with a browser fallback on career pages (`CAR` `calculate-category-fitscore`). Empty fit tables mean "not computed yet", not "no result"; VC's answer text should say so.
