# Ubuntu install and release preparation

Gate: `qa/gates/golive-launch.md` (Q1 launcher, Q3 nginx proxy, Q4 KB keys in the server `.env`, Q5 speakers from the KnowledgeBase team, Q7 Ubuntu). Voice remains gated by the current launcher, voice configuration, vetted crisis audio and explicit rollout approval. Nothing here runs by itself: these are the steps a person performs on the server.

1. **Packages.** `sudo apt install nginx certbot python3-certbot-nginx git` and Node 20 or newer plus pnpm (`corepack enable`).
2. **User and directories.** `sudo useradd --system --home /opt/vc --shell /usr/sbin/nologin vc`; `sudo mkdir -p /opt/vc /etc/vc`.
3. **Code.** Put the release at `/opt/vc` (`git clone` or copy), owned by `vc`. Then `sudo -u vc pnpm -C /opt/vc install --frozen-lockfile` (the launcher runs through `tsx`, a dev dependency, so install with dev dependencies).
4. **Environment.** Copy the "GO-LIVE LAUNCH BLOCK" of `.env.example` to `/etc/vc/vc.env`, fill in the values (`MONGODB_URL`, `VC_JWT_*`, `OLLAMA_API_KEY`, `VC_KB_BASE_URL`, `VC_KB_ANON_API_KEY`, `VC_CHAIN_MONTHLY_CAP_USD`), then `sudo chown root:vc /etc/vc/vc.env && sudo chmod 640 /etc/vc/vc.env`. Never commit it. If a surface flag is on and its config is missing the launcher refuses to start and names the variable.
5. **Speakers.** Put the KnowledgeBase team's speakers JSON at `/etc/vc/speakers.json` and keep `VC_SPEAKERS_FILE=/etc/vc/speakers.json`. Until it exists, delete the `VC_SPEAKERS_FILE` line: unset means an empty list and no speaker is named, while a set but missing file makes the launcher refuse to start.
6. **Student UI.** Build or copy the static student UI into `/opt/vc/apps/student` (the `golive-student-ui` unit).
7. **nginx and TLS.** First declare the request-limit zone at http level (the site file uses it): `echo 'limit_req_zone $binary_remote_addr zone=vcchat:10m rate=20r/m;' | sudo tee /etc/nginx/conf.d/vc-limit.conf` (conf.d files are included inside `http {}`; `limit_req_zone` is not valid inside `server {}`). Then `sudo cp infra/ubuntu/nginx-vc.conf /etc/nginx/sites-available/vc`, set `server_name`, `sudo ln -s /etc/nginx/sites-available/vc /etc/nginx/sites-enabled/vc`, `sudo nginx -t && sudo systemctl reload nginx`, then `sudo certbot --nginx -d <host>`. The checked-in site now exposes explicit public, partner/student chat and voice routes; unmatched `/v1/` paths remain 404. Review each enabled surface against its launcher gate. Student HTTP routes require `VC_CHAT_ENABLED=true`; voice WebSocket routes need their upgrade headers and token-safe access logging. This site does not define the Admin Next runtime or Admin proxy; DevOps must provide that deployment target separately.
8. **Service.** `sudo cp infra/ubuntu/vc-api.service /etc/systemd/system/`, `sudo systemctl daemon-reload`, `sudo systemctl enable --now vc-api`, then check `systemctl status vc-api`, `journalctl -u vc-api -n 50` (a `vc_api_listening` line) and `curl -s -o /dev/null -w '%{http_code}\n' -X POST https://<host>/v1/public/chat/turns -H 'content-type: application/json' -d '{"text":"hello"}'`. The anonymous route is served only when `VC_ANONYMOUS_ENABLED=true` and the A20 go-live gate (`qa/gates`) passes; otherwise the process refuses to start or answers 404.

## S13 release prerequisites (not a rollout receipt)

Use the existing [partner integration release preparation](../../docs/partner-integration.md) for both host build-time widget settings, exact commit asset paths, secret names and compatibility/rollback requirements. Do not copy only the historical anonymous-chat environment block: the current `apps/api/src/main.ts` validates the enabled runtime.

Central API/Admin DNS, TLS, service/image identity, eligible synthetic production test accounts and approved source/policy provisioning remain unresolved. An empty GitHub deployment list does not establish that no manual deployment exists. The reviewed release must supply these values and pass server-side `nginx -t` before an approved reload.

New widget releases are copied from one reviewed commit to `/opt/vc/releases/<40-character-commit>/widget/`; widget and voice asset hashes must match the release receipt. Preserve prior directories for rollback. Do not overwrite the old immutable v1 URL with new content.
